# Mage Knight Web v0.2 开发计划

更新日期：2026-09-05

## 1. 版本定位

`v0.2` 定位为“可重复单人核心”，目标是把 `v0.1` 的固定教学垂直切片升级为一局具备随机地图、时间压力、市场成长和征服目标的单人游戏。

本版本仍只提供 Tovak，不追求一次录完全部原版内容。它负责验证原版完整系统之间的组合关系；全部原版英雄、全部卡牌和正式场景留到 `v0.3 Core Complete`。

### 玩家可感知的完成状态

玩家能够：

1. 选择 seed 和难度，开始一局 Tovak 单人征服开发场景。
2. 选择战术牌，在 Dummy Player 的时间压力下进行昼夜轮次。
3. 从随机板块堆探索地图并揭示敌人、地点和奖励。
4. 使用动态高级行动、法术和单位市场完成牌组成长。
5. 与村庄、修道院、要塞、法师塔和一座城市互动或战斗。
6. 击败城市守军、结算名望和标准计分，得到明确胜负结果。
7. 保存、刷新、撤销、导出回放，并得到与连续运行相同的结果。

## 2. 范围

### 2.1 纳入 v0.2

- Tovak 的基础牌、升级线和一组完整可选技能。
- 战术选择、日夜轮次、Dummy Player 和单人轮末压力。
- 随机乡村/核心板块堆、合法板块放置、随机敌人标记和信息屏障。
- 高级行动、法术、普通/精英单位、神器四种奖励或市场牌区。
- 声望、名望、等级、护甲、手牌上限、指挥槽和标准回合末顺序。
- 村庄、修道院、要塞、法师塔、水晶矿、魔法林地和一座城市。
- Poison、Paralyze、Summon、Elusive、Unfortified、元素格挡和已有敌人能力的组合。
- 一个开发用单城征服场景；其规则必须使用原版场景钩子表达，不能写死在 UI。
- 市场、战斗、地图和终局计分所需的极简 Web 控件。
- `saveSchemaVersion: 2` 及 v0.1 存档的明确迁移或拒绝策略。

### 2.2 不纳入 v0.2

- 其他原版英雄和全部原版卡牌的批量录入。
- 完整官方 Solo Conquest、完整 First Reconnaissance 和全部场景。
- 多人、PvP、合作攻城和在线服务端。
- Krang、Lost Legion、Shades of Tezla。
- Apocalypse Dragon、Weather、Item Shop、Rise of the Forgemasters。
- 正式美术、动画、音效、账号和云存档。

## 3. 先决技术决策

当前 `engine.ts` 约 900 行，内容数据同时存在于 TypeScript 和 manifest。继续叠加市场、地点和能力会放大修改风险，因此 v0.2 前两个任务必须先处理边界：

- 内容只有一个权威数据源；运行时对象由校验后的内容包构建。
- 引擎按 `turn`、`map`、`combat`、`market`、`scenario` 拆分，但公开四接口保持兼容。
- 不为了未来多人把当前状态全面改成网络模型；Dummy 使用独立 `DummyState`，真人仍保持单玩家接口。
- 特殊规则使用能力处理器和场景钩子，不以敌人 ID、地点 ID 或场景 ID 写条件分支。
- v0.1 Golden hashes 在结构迁移时允许改变一次，但必须提供逐字段迁移说明和新的固定 hash。

## 5. 任务拆分

### V02-01 单一内容源和模块注册表

**目标**：消除 manifest 与 `tutorial-content.ts` 的重复数据，建立未来原版/扩展模块共同使用的内容加载方式。

**交付物**：

- `ContentModuleManifest`：`id`、`version`、`requires`、`conflicts`、实体集合和本地化键。
- `ContentRegistry`：按稳定 ID 查询卡牌、技能、单位、敌人、地点、板块和场景。
- 从 JSON 构建运行时内容；中文名称进入本地化字段，英文 ID 保持稳定。
- 模块依赖、重复 ID、悬空引用和资源 alias lint。
- v0.1 内容迁入 `core` 模块，运行结果不变。

**完成判定**：不再手工维护两份卡牌/敌人数值；关闭模块后注册表中不存在该模块实体。

**测试**：`ST-200` schema；`ST-201` 重复/悬空引用；`CT-200` 模块依赖；`GR-200` v0.1 回放兼容。

### V02-02 引擎模块化重构

**目标**：在不新增规则的前提下拆分 900 行主引擎，建立后续规则的所有权边界。

**交付物**：

- `turn/`、`map/`、`combat/`、`market/`、`scenario/`、`effects/` 模块。
- 公共 `CommandHandler`、事件创建器和原子资源支付工具。
- `executeIntent` 只负责通用校验、路由、提交事件和不变量检查。
- 引擎继续不依赖 React、DOM、IndexedDB 或具体 UI 文案。

**完成判定**：公开 API 不变；v0.1 全部测试及 Golden Replay 通过；规则处理器不存在循环依赖。

**测试**：`ST-210` 包边界；`CT-210` 命令路由；`CT-211` 失败原子性；`GR-210` 旧回放。

### V02-03 通用区域、决策和持续效果

**目标**：补齐市场、技能和复杂卡牌所需的通用状态能力。

**交付物**：

- 统一实体区域移动，覆盖 deck、hand、play、discard、removed、offer、inventory、skills、set-aside。
- 通用 `DecisionRequest`：选择实体、目标、数量、顺序和继续点。
- DSL 增加 `repeat`、`draw`、`discard`、`convert`、`choose-one`、`conditional`、`create-lasting-effect`。
- 持续到回合末/下回合开始/轮末的效果生命周期。

**完成判定**：实体不会同时存在于两个区域；选择中可保存恢复；持续效果只在指定窗口失效。

**测试**：`PT-220` 区域唯一性；`CT-220` 复合效果；`CT-221` 选择恢复；`CT-222` 效果过期顺序。

### V02-04 完整回合、战术和 Dummy Player

**目标**：按规则书补齐单人时间系统，而不是继续由固定牌序推动回合。

**交付物**：

- 回合前窗口、普通回合、休息、宣布轮末和严格回合结束九步顺序。
- 昼夜战术牌选择与顺位。
- Dummy 牌库、颜色翻牌、水晶加速和牌库耗尽触发轮末。
- 新轮市场刷新、Source 重掷、技能/单位重置和持续效果处理。

**完成判定**：Dummy 不进入地图或战斗；相同 seed 的战术、Dummy 翻牌和轮末时点稳定。

**测试**：`CT-230` 回合末顺序；`CT-231` 战术；`CT-232` Dummy 翻牌；`IT-230` 昼夜整轮；`GR-230` 固定轮次 hash。

### V02-05 随机地图和标记揭示

**目标**：从固定两块板图升级为规则驱动的板块堆和探索。

**交付物**：

- 乡村/核心板块堆、方向和场景地图形状。
- 合法边界探索、板块全局坐标变换和占位冲突检查。
- 游荡敌人、要塞守军、冒险地点标记堆及揭示事件。
- 威胁区、安全空间、强制战斗和回合末撤退。
- 所有随机揭示建立信息屏障。

**完成判定**：任意合法 seed 不产生重叠、断裂或不足七格的板块；未知标记揭示后不可越屏障撤销。

**测试**：`PT-240` 500 个地图 seed；`CT-240` 放置形状；`CT-241` 标记屏障；`IT-240` 强制战斗/撤退；`GR-240` 地图 hash。

### V02-06 市场、声望和升级

**目标**：建立原版成长经济。

**交付物**：

- 高级行动、法术、普通/精英单位市场和神器奖励堆。
- 新轮市场刷新顺序和修道院高级行动补充。
- 声望轨道及 Influence 修正。
- 完整等级线：护甲、手牌上限、指挥槽、Tovak 技能与高级行动选择。
- 超出指挥槽时的解散/放弃决策。

**完成判定**：市场刷新和购买均可从事件日志还原；多次升级按回合末顺序逐级完成。

**测试**：`CT-250` 市场刷新；`CT-251` 声望修正；`CT-252` 单位槽选择；`IT-250` 连续升级；`ST-250` 市场中途存档。

### V02-07 基础地点闭环

**目标**：用同一地点接口实现原版常见互动和征服逻辑。

**交付物**：

- 村庄：招募、治疗。
- 修道院：招募、治疗、学习高级行动、焚烧。
- 要塞：强制攻城、占领后手牌上限收益。
- 法师塔：强制攻城、占领奖励法术。
- 水晶矿和魔法林地的回合末收益。
- 一座城市：多守军、盾牌、颜色互动和征服状态。

**完成判定**：地点规则通过能力/钩子注册；通用引擎没有按地点 ID 分支。

**测试**：`CT-260` 各地点合法动作；`IT-260` 要塞；`IT-261` 修道院焚烧；`IT-262` 法师塔；`IT-263` 城市征服。

### V02-08 战斗能力补齐

**目标**：覆盖原版内容录入前最关键的组合式敌人能力。

**交付物**：

- Fire/Ice/Cold Fire 攻击与对应有效/无效格挡。
- Poison、Paralyze、Summon、Elusive、Unfortified、Arcane Immunity、Assassination、Cumbersome。
- 单位元素抗性、单位治疗和摧毁。
- 多目标攻击及同阶段多次独立攻击。
- 计算明细统一输出基础值、修正、抗性和最终值。

**完成判定**：能力组合由标签处理器叠加，不为单个敌人写专用逻辑。

**测试**：`CT-270` 至 `CT-279` 每项能力；`PT-270` 能力组合顺序；`IT-270` 三敌人混合遭遇。

### V02-09 Tovak 核心内容批次

**目标**：录入足以支撑多局成长的经核对原版内容，而不是一次录完整盒。

**建议批次**：

- Tovak 全部技能。
- 16 张基础行动牌复核。
- 至少 12 张高级行动、8 张法术、8 张神器。
- 至少 12 个普通单位、8 个精英单位。
- 每类基础敌人至少 4 个，覆盖 V02-08 的能力组合。
- 战术牌、板块、地点和城市所需标记。

**完成判定**：每个实体有英文逻辑名、中文显示名、来源页/组件映射、数值、规则文本摘要和 asset alias；内容 lint 无警告。

**测试**：`ST-280` 数量和来源；`ST-281` 效果节点覆盖；`CT-280` 每张牌至少一个效果测试；`GR-280` 固定内容构筑。

### V02-10 单城征服开发场景和计分

**目标**：提供一个能验证原版系统组合、但不冒充正式 Solo Conquest 的开发场景。

**交付物**：

- 场景配置：地图形状、轮数、城市等级、Dummy 配置、胜负条件和难度参数。
- 城市征服后立即结束或完成当前回合的明确场景裁定。
- 基础名望、冒险、知识、战利品、领导力等已适用计分项。
- 胜利、轮数失败、击倒后继续三条人类可读回放。

**完成判定**：终局只由场景触发器决定；改变难度只修改配置，不复制场景处理器。

**测试**：`IT-290` 胜利；`IT-291` 轮数失败；`GR-290` 三条固定 hash；`PT-290` 20 个场景 seed。

### V02-11 Web 操作层

**目标**：保持当前极简排版，同时让新增系统可完整操作和解释。

**交付物**：

- 新游戏配置：seed、难度、场景。
- 战术选择、Dummy 状态和轮末压力。
- 可平移/缩放地图、地点/敌人详情。
- 市场购买、升级、单位解散和奖励选择。
- 城市多守军战斗及终局计分表。
- 继续使用普通 HTML 和简洁居中布局，不引入装饰性仪表盘。

**完成判定**：UI 只渲染引擎合法意图；所有强制选择可保存恢复；1024×768、1280×720、1440×900 可操作。

**测试**：`UI-300` 至 `UI-305`；`E2E-300` 新游戏到市场成长；`E2E-301` 探索到城市征服；`E2E-302` 中途刷新继续。

### V02-12 存档迁移和发布门禁

**目标**：把新增状态纳入确定性、迁移和发布证据。

**交付物**：

- `saveSchemaVersion: 2`、迁移器和不兼容内容提示。
- 回放格式记录启用模块、场景、难度和内容 hash。
- v0.1 教学回归、v0.2 征服回放、内容覆盖矩阵和发布说明。
- Chromium、Firefox、WebKit 核心流程。

**完成判定**：干净安装后的单一验收命令全部通过；至少 20 个固定场景 seed 和 200 个随机规则 seed 无不变量错误。

**测试**：`ST-310` 存档迁移；`GR-310` 连续/恢复一致；`PT-310` 200 seed；`E2E-310` 三浏览器；`E2E-311` 保存/撤销/胜利。

## 8. 工期与模型建议

建议按一名开发者配合 Codex 预留 4-6 周，其中内容核对和组合规则 QA 至少占一半时间。

- V02-01、V02-02：使用 Sol High；公开协议或迁移审查用 Sol Xhigh。
- V02-03、V02-04、V02-06、V02-08：使用 Sol Xhigh，属于高耦合规则任务。
- V02-05、V02-07、V02-09：使用 Sol High；批量结构化录入可用 Terra High，之后必须由 Sol High 复核。
- V02-10、V02-12：使用 Sol Xhigh，重点是确定性、场景边界和回归判定。
- V02-11：使用 Terra High 实现，Sol High 复核 UI 与引擎边界。

## 9. 立即执行建议

下一次开发只提交 `V02-01`，不要同时录入新卡牌或改 UI。其完成后必须先证明：

1. v0.1 内容由单一 JSON 内容包加载。
2. 当前 45 项单测、Golden Replay 和浏览器教学流程不变。
3. 重复 ID、缺失引用、错误模块依赖和未支持效果会在构建前失败。
4. 新内容模块可以注册和关闭，关闭后不泄漏实体。

V02-01 通过后再执行 V02-02。若在内容管线未稳定前批量录入原版内容，后续 schema 调整会造成大范围返工。
