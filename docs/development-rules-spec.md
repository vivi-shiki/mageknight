# Mage Knight 单人 Web 版开发规则规格

## 1. 文档目的

本文把桌游自然语言规则改写为可实现、可测试、可扩展的开发规格。它不逐字复制规则书，也不枚举每张卡牌；卡牌、英雄、单位、敌人、地点和场景的具体数值应进入内容数据层。

本规格覆盖：

- 原版核心规则。
- The Lost Legion、Krang、Shades of Tezla 三个官方扩展。
- The Apocalypse Dragon 粉丝扩展。
- Rise of the Forgemasters、Atlantean Weather、Item Shop 可选粉丝模块。
- 单人游戏所需 Dummy Player 和 Proxy Player。

暂不实现玩家对玩家战斗和实时多人交互。合作攻城等多人规则只保留数据和事件接口。

## 2. 核心设计原则

### 2.1 权威状态

游戏的唯一真相是可序列化的 `GameState`。画面、动画、音效和弹窗不得直接修改状态，只能提交命令。

每次玩家操作遵循：

`Intent -> Validation -> Domain Events -> Reducer -> New State -> UI`

### 2.2 确定性

- 所有洗牌、抽牌、掷骰和随机敌人都由带种子的随机数生成器完成。
- 相同初始状态、种子和命令序列必须得到完全相同的终局状态。
- 保存文件必须记录内容版本、启用模块、场景 ID、随机种子和事件日志版本。

### 2.3 规则优先级

`场景特例 > 扩展/FAQ > 卡牌或实体文本 > 基础规则`

禁止依赖模糊的全局“特殊规则总是覆盖普通规则”。每个覆盖必须落实为明确的条件、替换规则或事件钩子。

### 2.4 信息揭示与撤销

玩家可以撤销到最近一次信息屏障之后的任意状态。以下行为建立信息屏障：

- 揭示地图板块。
- 翻开未知敌人、遗迹或任务牌。
- 抽取未知卡牌。
- 掷骰或重新掷骰。
- 单人 AI/Dummy/Proxy 根据隐藏信息作出行为。

执行信息屏障后，只能撤销屏障之后的操作，不能重新选择屏障之前的路径来刷随机结果。调试模式可允许完全回放，但正式模式不允许。

## 3. 游戏状态模型

最低状态组成如下：

```ts
type GameState = {
  schemaVersion: number;
  contentVersion: string;
  seed: string;
  enabledModules: ModuleId[];
  scenario: ScenarioState;
  round: RoundState;
  map: MapState;
  markets: MarketState;
  decks: Record<DeckId, DeckState>;
  players: PlayerState[];
  enemies: Record<EntityId, EnemyState>;
  encounter?: EncounterState;
  pendingDecision?: DecisionRequest;
  delayedEffects: DelayedEffect[];
  eventLog: DomainEvent[];
  checkpoints: UndoCheckpoint[];
};
```

必须把以下区域建模为不同的卡牌区：牌库、手牌、打出区、弃牌堆、移出游戏区、暂置区、单位区、技能区、库存、市场和场景专用区。移动卡牌时不得只修改一个数组；应使用统一的 `moveEntity` 事件保证卡牌只存在于一个区域。

## 4. 游戏与场景生命周期

### 4.1 创建游戏

1. 选择场景、难度、英雄、启用模块和可选变体。
2. 运行模块兼容性检查。
3. 根据场景建立地图形状、板块堆、敌人堆、市场、城市和特殊实体。
4. 创建玩家初始牌库、等级、护甲、手牌上限、声望、名望和水晶库存。
5. 创建 Dummy Player；使用 Apocalypse 的 Proxy 变体时创建 Proxy Player。
6. 执行场景的 `onSetup` 钩子。
7. 进入第一轮。第一轮跳过常规“准备新一轮”中的刷新步骤，但仍完成场景要求的初始准备。

### 4.2 场景结束

每个玩家回合结束后检查 `scenario.endTrigger`。触发后按场景规则给予其他实体最后一回合或立即结束。

终局只由场景决定：轮数上限、目标完成、Boss 击败、城市征服或失败条件。通用引擎不得假定“征服城市即获胜”。

终局结算分为：

- 基础名望。
- 标准成就称号。
- 场景专属加减分。
- 扩展模块分数，如任务分、阵营代币、Forgemasters 物品。

## 5. 轮结构

### 5.1 准备新一轮

第二轮及以后依次执行：

1. 日夜翻转。
2. 重掷 Source 中全部法力骰，并标记当前日夜下不可用的黑色或金色骰。
3. 刷新单位市场：未购买单位回到对应牌库底；按是否已揭示核心板块决定普通/精英单位组成；每个未烧毁修道院增加一张高级行动牌。
4. 刷新高级行动市场：底部牌回牌库底，其余下移，顶部补一张。
5. 同样刷新法术市场。
6. 收回上一轮战术牌并展示当前日夜的战术牌。
7. 所有玩家重置横幅、技能和单位；受伤单位保持受伤。
8. 处理需要在新轮开始支付的维持费用。
9. 将弃牌、手牌和牌库按规则合并洗牌，抽至修改后的手牌上限。
10. 执行启用模块的 `onRoundPrepare` 钩子，例如天气和任务市场刷新。

### 5.2 选择战术

- 名望最低者先选；同名望时，上一轮顺位更靠后者先选。
- 执行“取得此战术时”的即时效果。
- 按战术编号从小到大建立本轮顺位。
- 单人 Dummy/Proxy 按其规则取得战术。

### 5.3 轮内循环

玩家按顺位循环行动。牌库在回合开始时为空的玩家可以宣布轮末；若手牌也为空则必须宣布。宣布后其他玩家各得到最后一回合。

单人模式中 Dummy/Proxy 的牌库耗尽同样触发轮末。最后一回合结束后不得再使用“其他玩家回合”效果。

## 6. 玩家回合

### 6.1 回合前窗口

解析上一回合持续到“你的下回合开始”的效果，然后允许使用“回合前/其他玩家回合”效果。一个效果解析过程中不能插入另一个普通效果，只有明确的反应窗口可以插入。

### 6.2 回合类型

玩家必须选择一种：

1. 普通回合：可选移动，随后可选或强制执行一个行动。
2. 休息：不能移动或执行行动，但可执行允许的特殊效果和治疗。
3. 宣布轮末：满足牌库条件时放弃本回合。

普通回合的行动只有一个：

- 与敌人战斗。
- 与地点互动。
- 执行标记为“作为本回合行动”的卡牌效果。
- 多人模式中的 PvP，当前版本禁用。

某些移动会强制进入战斗，此时不能再选择其他行动。

### 6.3 休息

- 标准休息：弃掉一张非伤牌，并可弃任意数量手牌中的伤牌。
- 慢速恢复：若手牌全是伤牌，弃掉一张伤牌。
- 休息产生的是弃牌，不是治疗；伤牌会在下一轮重新洗回牌库。

### 6.4 回合结束顺序

顺序是强规则，不能交换：

1. 归还并重掷本回合从 Source 使用的法力骰。
2. 若停在不安全位置，执行强制撤退；每回退一格获得一张伤牌，直到安全位置。
3. 清理打出区；未消耗的纯法力消失，水晶仍在库存。
4. 处理所在空间的回合末收益，如魔法林地和水晶矿。
5. 领取战斗奖励，并按玩家指定顺序处理可选奖励。
6. 处理本回合跨越的所有升级线。
7. 弃任意数量非伤手牌；若本回合一张牌都未打出，至少弃一张非伤牌。
8. 抽到修改后的手牌上限。牌库耗尽时通常不洗弃牌堆。
9. 执行 `onTurnEnd` 和持续效果过期。

## 7. 卡牌、技能、单位和法力

### 7.1 行动牌

- 可直接使用基础效果。
- 支付牌面颜色的一点法力后使用强化效果。
- 同一张牌一次只能选择一种方式。
- 非伤牌可横置为 `Move 1`、`Influence 1`、`Attack 1` 或 `Block 1`；横置不能产生远程、攻城或元素属性。

### 7.2 法术

- 支付牌面颜色法力使用基础效果。
- 仅在夜晚，可再支付一点黑色法力使用强化效果。

### 7.3 神器与横幅

- 神器可使用普通效果，或移出游戏以使用强效果。
- 横幅可附着到单位，附着期间只能使用其普通效果。
- 单位被解散/摧毁、改挂另一横幅时，原横幅进入弃牌堆。

### 7.4 单位

- 单位占用一个指挥槽。
- 新招募单位为 Ready 且未受伤。
- Ready 且未受伤的单位可激活一个能力并转为 Spent。
- 受伤单位不能激活，也不能承受新的普通伤害分配。
- 一轮开始时单位转为 Ready，但受伤状态不清除。

### 7.5 技能

基础技能分为：每轮一次、每轮一次且持续到下回合开始、每回合一次。Krang 的 Flip Back 技能属于第四类：使用后翻面，但可在满足技能自身条件时于同一轮翻回。

### 7.6 法力

- 四种基础色：红、蓝、白、绿；可作为纯法力或最多三枚同色水晶储存。
- 金色只在白天作为任意基础色；黑色只在夜晚用于规定效果。
- 每回合通常最多使用 Source 中一颗法力骰；取骰时必须立即用于合法支付。
- 纯法力在回合末消失；水晶可长期保留。
- 获得第四枚同色水晶时，通常改为本回合的一点同色纯法力。

## 8. 地图与移动

### 8.1 坐标与空间

每个地图空间使用轴向六边形坐标 `(q, r)`。板块仅是生成和素材分组；移动、距离、相邻、墙和实体归属都基于全局空间坐标。

空间包含：地形、地点、可见性、驻军、游荡敌人、覆盖物、天气、毁坏状态、玩家和场景标记。墙属于两格之间的边，不属于某一格。

### 8.2 移动点

- 玩家在移动阶段产生 Move 点并支付地形费用。
- 不可进入山脉和湖泊，除非效果明确允许。
- 未使用 Move 点通常不能带入行动或战斗。
- 进入未征服要塞结束移动并强制攻城。
- 经过游荡敌人的威胁区会触发战斗；可主动挑战相邻游荡敌人。
- 进入其他玩家空间的规则在单人版禁用。

### 8.3 探索

在合法边界支付探索费用后，从板块堆揭示一块新板块并按场景形状放置。板块和其上的未知标记一经揭示即建立信息屏障。

### 8.4 安全空间

回合必须结束在安全空间。敌对要塞、敌人占据空间、部分场景特殊空间均可能不安全。若战斗失败或效果结束后位于不安全空间，执行强制撤退。

## 9. 地点互动

互动只允许在友好或已征服的有人地点进行。声望轨道提供 Influence 修正，标记为不可互动的位置直接禁止互动。

典型操作：

- 村庄：招募允许在村庄出现的单位、购买治疗。
- 修道院：招募、购买治疗、学习单位市场中的高级行动；也可选择焚烧并进入战斗。
- 已征服要塞：按地点规则提供手牌上限收益。
- 已征服法师塔：学习法术。
- 已征服城市：按城市颜色购买单位、卡牌、治疗或水晶等。

同一次互动可执行多个合法购买，只要资源足够。招募单位超过指挥槽时必须先解散一个单位或放弃招募。

## 10. 敌人战斗

### 10.1 建立遭遇

遭遇包含玩家、敌人列表、地点工事、跨墙工事、场景修正、已触发能力和奖励。敌人揭示后建立信息屏障。

### 10.2 四阶段

1. 远程/攻城攻击。
2. 格挡。
3. 分配伤害。
4. 普通攻击。

每个阶段只能使用该阶段合法的效果。

### 10.3 远程/攻城攻击

- 选择一组目标，攻击总值达到目标护甲总和则全部击败。
- 目标中有工事保护的敌人时，只能使用攻城攻击。
- 同一阶段可进行多次独立攻击。
- 敌人抗性会使对应攻击贡献减半，按规则完成取整。

### 10.4 格挡

- 每个敌人攻击单独格挡，不能把多个敌人攻击合并成一个格挡目标。
- 有多段攻击的敌人，每一段分别格挡；全部格挡才算“成功格挡该敌人”。
- 元素克制决定格挡是否有效；无效格挡贡献减半。
- Swift 需要两倍格挡。
- 攻击降到 0 视为成功格挡。

### 10.5 分配伤害

逐个处理未被击败且未成功格挡的攻击：

1. 先可分配给未受伤单位。单位受到伤牌后，伤害减去其护甲。
2. 单位若抗该攻击元素，先无伤减一次护甲；仍有剩余时再受伤并再减一次护甲。
3. 剩余伤害分配给英雄。每取得一张伤牌，伤害减去英雄护甲，直到归零。
4. 应用 Brutal、Poison、Paralyze、Assassination 等附加能力。

### 10.6 普通攻击

工事失效，可使用普通、远程和攻城攻击。仍按目标护甲、抗性和多次独立攻击规则结算。

### 10.7 战斗结果

- 游荡敌人：击败后移除并按类型调整声望。
- 冒险地点：满足全部击败条件后放置玩家盾牌并在回合末领赏。
- 要塞：全部守军击败后占领；失败则退回攻击发起格。
- 法师塔：占领奖励法术。
- 修道院：焚烧成功后成为空地，奖励神器。
- 城市：按击败守军数量放置盾牌并计算城市领袖。

## 11. 伤牌、治疗、击倒和升级

### 11.1 伤牌

- 英雄受伤时伤牌进入手牌。
- 伤牌不能横置、普通弃置或作为一般支付。
- 休息只把伤牌放进弃牌堆；治疗才把伤牌退回伤牌堆。
- Poison 对英雄额外把伤牌放入弃牌堆；对单位通常造成两张伤牌。

### 11.2 治疗

- 非战斗期间可使用治疗点。
- 1 点治疗移除英雄手牌中的一张伤牌。
- 治疗单位需要等于其等级的治疗点，每次移除一张单位伤牌。
- 战斗中不能治疗，进入战斗前未使用的治疗点消失。

### 11.3 击倒

英雄在一次战斗中获得到手牌的伤牌数量达到或超过未修正手牌上限时被击倒。击倒不自动结束游戏，但会限制后续动作；具体处理进入显式 `KnockoutState`，避免用 UI 提示代替规则状态。

### 11.4 升级

名望越过等级线后，在回合末逐级处理：

- 指挥等级：提升护甲/手牌上限并获得一个指挥槽。
- 技能等级：从两个本英雄技能中选一个并获得高级行动；也可选公共技能并按规则取得市场底部高级行动。

若同一回合有单位奖励和新增指挥槽，可延后单位奖励到升级后领取。

## 12. 基础敌人能力

必须把能力建模为组合式标签和处理器，不要为每种敌人写独立战斗代码。

| 能力 | 开发语义 |
| --- | --- |
| Swift | 所需格挡翻倍 |
| Brutal | 未格挡伤害翻倍 |
| Poison | 英雄/单位获得额外伤牌 |
| Paralyze | 受伤单位摧毁；英雄弃非伤手牌 |
| Summon | 格挡阶段临时抽取敌人代替攻击，结算后弃掉 |
| Fortified | 远程阶段只能用攻城攻击；叠加工事时可完全禁止远程阶段攻击 |
| Physical/Fire/Ice Resistance | 对应攻击贡献减半，并免疫部分同色非攻击效果 |
| Elusive | 远程阶段用高护甲；成功格挡全部攻击后，普通攻击阶段用低护甲 |
| Unfortified | 忽略地点和墙提供的工事 |
| Arcane Immunity | 免疫非攻击/非格挡效果，但其攻击仍可被修改 |
| Assassination | 未格挡伤害只能给英雄 |
| Cumbersome | 格挡阶段可新产生并支付 Move 点降低攻击 |
| Multiple Attacks | 多个攻击值分别结算 |

## 13. 官方扩展规则差分

### 13.1 The Lost Legion

新增地图规则：

- 墙：普通跨越额外 `Move 1`，不能被地形减费抵消；直接移动效果可忽略。跨墙攻击会增加工事层级；游荡敌人不会隔墙触发。
- Maze/Labyrinth：行动阶段另付 `2/4/6 Move`，最多携带一个指定 Ready 单位，按路径层级战斗并领取不同奖励；每条路径每局只能被一名玩家完成。
- Deep Mine：回合末从地点允许的多个颜色中选一枚水晶。
- Refugee Camp：可招募任何市场单位，不同招募地点类型产生额外 Influence 成本。

新增单位规则：

- Thugs 反转声望加成，Heroes 将声望修正翻倍，且同次互动不能同时招两类。
- Thugs 承伤、Heroes 参与攻城需要战斗中额外支付 Influence。
- Magic Familiars 需要招募和每轮维持法力。
- Delphana Masters 只能通过互动取得，且一次激活可支付多种法力使用多个不同能力。

新增敌人和效果：Elusive、Assassination、Cumbersome、Unfortified、Arcane Immunity、多段攻击、击败敌人时声望奖励、“作为行动”的卡牌效果、延后到下次抽牌的手牌上限修正。

Volkare 作为场景 Boss：

- 有地图实体、等级、军队、专属牌库和法力骰。
- 通常忽略地形、墙和地点移动，不触发游荡敌人。
- 战斗仍使用四阶段，但 Volkare 本体不可被攻击；清空其军队才击败他。
- Volkare 额外进行带 Brutal 和 Assassination 的随机攻击。
- 若远程阶段清空全部军队，Volkare 不再攻击。
- 单人版保留他主动移动和攻击玩家的场景行为；合作分兵接口暂不做 UI。

### 13.2 Krang Character Expansion

只有一项新的通用语义：`FlipBackSkill`。技能翻至背面后，在同一轮满足其自身条件时可翻回正面，再次使用。每个技能的翻回条件是数据，不写死在引擎中。

### 13.3 Shades of Tezla

新增敌人能力：

- Defend：本次战斗中第一次攻击目标获得护甲加成；多个 Defend 必须分配给不同目标。
- Vampiric：其攻击每使一个单位受伤或给英雄一张到手伤牌，本场战斗护甲加 1。
- Ambush：符合视线、距离和墙条件时，可从两格外被玩家移动触发。
- Pursuit：敌人按场景标记追逐英雄，在英雄移动结束后向其移动；已相邻且可攻击时强制进入行动战斗。

新增位置覆盖物：Hidden Valley、Necropolis、Graveyard。覆盖物修改地点和日夜规则，但不一定改变底层地形移动费用。

阵营敌人必须记录 `factionId`。召唤敌人通常来自同阵营；击败后可获得阵营代币。阵营首领是场景 Boss，使用独立大型状态而非普通圆形敌人。

### 13.4 跨官方扩展兼容

- 敌人能力可叠加，处理顺序由阶段和事件优先级决定。
- 墙、地点工事、敌人 Fortified 和 Unfortified 必须分别记录，不能压缩成一个布尔值。
- 召唤、附身、阵营和 Boss 都应通过组合实体实现，避免复制敌人定义。

## 14. Apocalypse Dragon 粉丝扩展

### 14.1 附身敌人

附身敌人由“基础圆形敌人 + 附身模板”组合产生。模板可修改护甲、最上方攻击、名望，增加精神攻击，并指定击败后的阵营代币奖励。两个实体的原始 ID 和来源牌堆都要保留，便于结算后正确弃置。

### 14.2 精神攻击与格挡

- 精神攻击不是物理或元素攻击，不能获得普通攻击能力加成。
- 只有 Psychic Block 有效；其他 Block 减半。
- Influence 可当 Psychic Block，并可从同一来源拆分给多个精神攻击。
- 精神伤害分配给单位时，以单位等级代替护甲；给英雄仍用英雄护甲。

### 14.3 新地点

- Oasis：可招募村庄单位、治疗、买卖水晶；在此开始回合获得 `Move 2`。
- Ziggurat/Pyramid：三层冒险地点。每层先掷骰处理陷阱，再选择战斗离开或继续上层。不能使用单位；奖励、敌人颜色和已占层级按地点数据决定。

### 14.4 Apocalypse Dragon

- 地图模型覆盖三个空间，但逻辑上是一个 Boss 实体。
- 有 War、Death、Famine、Pestilence 四个可攻击头和一个不可攻击的 Control 头。
- 每个头有独立等级、护甲、攻击和已被盾牌标记的等级。
- 单次攻击达到护甲的整数倍时可下降多个等级；实际等级指示物在整场战斗结束后统一下降。
- Control 头等级等于其他头的最高等级，并按等级提供攻击、召唤或全体加成。
- 四个可攻击头全部击败后 Control 头同时击败。
- 单人版只需一名玩家进入 Boss 覆盖的任一空间；合作分配头部留接口。

### 14.5 Four Horsemen

每个 Horseman 是地图敌人，数值来自独立等级卡。玩家可在同格以行动挑战，并可与该格要塞、触发的游荡敌人、主动挑战的相邻敌人合并为同一战斗。击败后获得名望和 Apocalypse 阵营代币并记录击败者。

### 14.6 任务

任务市场初始两张，最终容量为玩家数加二；单人固定四张。任务分为：

- Simple：单步骤，无进度标记。
- Personal：一名玩家独占进度；同时最多进行一个个人任务。
- Independent：各玩家分别记录进度。
- Collective：全局共享进度。

任务步骤按编号完成，可有互斥选项。完成步骤可移动任务到市场最左、获得任务分、放置地图标记或奖励。完成、失败、放弃和每轮刷新都必须清理关联盾牌、地图标记和附属卡。

单人版仍使用统一多玩家数据结构，但只实例化一个玩家进度槽。

### 14.7 战役与 Proxy Player

战役保存跨场景解锁内容、上局牌池、声望衰减、起始等级和阵营代币。伤牌不会跨场景保留。

Proxy Player 是确定性规则 AI：以目标牌颜色选择目标类型，按距离移动，自动探索、征服、焚烧或互动。所有平局由固定规则或玩家选择请求解决。Proxy 计入 Source 骰和单位市场人数。

## 15. Rise of the Forgemasters

该扩展对效果解析器提出以下新增语义：

- Immediate、Triggered Delayed、Lasting Delayed 三类效果。
- Modifiable Effect，只允许数值奖励/惩罚作用到规定的 Move、Influence、Block、Attack 等效果。
- Bonus 先加到第一个可修改效果；Penalty 尽可能依次扣除，未能扣除的点数转化为伤牌。
- Color Scarcity：在全部相关法力骰中出现次数最少的基础色，允许并列。
- Tuck：展示后放到牌库底；不能 tuck 伤牌或在牌库为空时执行。
- Prepare：放到牌库顶，可处理伤牌且不必公开顺序。
- Mana Shard：视为水晶但使用时带 `-1`，未能应用惩罚会受伤；不计终局水晶分。
- Innate Fortification、Arcane Vulnerability、Arcane Immunity 的互斥和覆盖。
- Potion：库存中的四色双面代币，可增强水晶、消除 shard 惩罚、给单位增益或给敌人减益。
- Restricted Move：不能支付地形费用，但可用于探索、过墙、迷宫或降低 Cumbersome。
- Poisonous Attack：可额外计算一次，但目标延迟到战斗末击败并减少名望。
- Assassinating Attack：对单一 Elusive 目标按规则额外计算，并可绕过地点工事但不绕过 Innate Fortification。
- Forked Composite Effect：按顺序解析多个子效果，奖励和惩罚不能反向影响父效果。
- 神器默认无色，但在玩家自己的回合可按效果要求视为任意颜色组合。

实现建议：基础版阶段先让 DSL 支持这些语义的结构占位，不在 MVP 中录入全部 Forgemasters 卡牌。

## 16. Weather 和 Item Shop

### 16.1 Atlantean Weather

- 起始板块不抽天气。
- Continental：每轮为每一地图行抽一张当前日夜天气，影响该行全部板块。
- Regional：为玩家所在板块及相邻板块抽天气，以天气标记和轨道维护持续效果。
- 跨板块攻击或互动使用玩家所在板块的天气，目标所在板块天气不参与。
- 新轮清除上一轮天气，再从另一套日/夜牌库抽取。

天气实现为 `AreaModifier`，不能直接永久改写地形或敌人数据。

### 16.2 Item Shop

- 村庄、修道院和城市互动时可访问三张物品市场。
- 物品可用金币、Influence 或混合支付；一次可买多件。
- 击败敌人获得其名望一半的金币；具体取整规则需要版本确认。
- 偷窃消耗本回合行动，以不同声望代价掷不同数量的六面骰获得金币。
- 装备不进入 Deed 牌库，留在玩家区；同类型/特征冲突时必须替换。
- Exhaust 物品横置到轮末；Discard 物品为一次性效果。
- 护甲物品抗性按单位抗性方式结算。

金币、装备槽和物品市场应属于独立模块状态。禁用模块时保存文件中不得残留相关资源。

## 17. 单人模式

### 17.1 Dummy Player

Dummy 不在地图上。它选择战术、按翻牌颜色和水晶数量消耗牌库，并用牌库耗尽推进轮末。Dummy 的目标是施加时间压力，不参与地图和战斗。

### 17.2 Proxy Player

Proxy 是可选替代。它使用英雄棋子、参与市场人数计算、在地图上行动并可夺取地点。Proxy 的行为由公开规则自动执行，只有规则允许的平局才向真人请求选择。

### 17.3 AI 边界

第一版不开发“会规划整回合的 Mage Knight AI”。Dummy/Proxy 都是规则机器人。若未来增加完整 AI，应只调用同一套合法行动查询和命令接口，不得访问隐藏牌序或绕过规则验证。

## 18. 多人预留

当前不实现多人，但核心状态从第一天保留 `players[]`、`activePlayerId`、可见性过滤和 `DecisionRequest.ownerIds`。

未来多人所需：

- 服务器权威执行命令。
- 按玩家隐藏手牌、牌库顺序和私有选择。
- 回合前反应窗口、PvP 防守选择、合作攻城分配和同步规划。
- 断线重连、超时托管、观战和事件日志脱敏。
- 合作攻城可以串行结算，不需要实时帧同步。

## 19. 必须成立的不变量

1. 每张卡牌和实体同时只属于一个区域或容器。
2. 牌库顺序只有随机事件、明确效果或初始化能改变。
3. Source 中每颗骰同时只有一个占用者。
4. 玩家单位数不能超过指挥槽，除非有明确持续效果。
5. 受伤单位不能被激活或再次正常分配伤害。
6. 每个战斗阶段只接受该阶段合法命令。
7. 未完成的 `DecisionRequest` 存在时，只接受该请求允许的命令。
8. 每次资源支付都必须是原子操作；失败时状态不变。
9. 禁用模块不能产生该模块实体或事件。
10. 存档恢复后继续执行，结果必须与不中断运行一致。

## 20. 首批规则验收场景

1. 白天使用金色法力强化行动牌，夜晚同操作被拒绝。
2. 探索后尝试撤销到探索之前，正式模式拒绝。
3. 攻击有工事的物理抗性敌人，远程无效、攻城减半、普通阶段可攻击。
4. Swift + Fire Attack 使用普通 Block 与 Ice Block 的结果正确。
5. Poison 单位伤害产生两张单位伤牌，英雄伤害分别进入手牌和弃牌堆。
6. Elusive 敌人未完全格挡时保持高护甲，完全格挡后使用低护甲。
7. 跨墙攻击叠加工事，Unfortified 敌人正确忽略地点和墙的工事。
8. Volkare 远程阶段军队清空后不进行本体攻击。
9. Krang 技能满足条件翻回并可同轮再次使用。
10. Pursuit 敌人在玩家移动结束后走向最近合法空间，并按规则触发攻击。
11. 附身敌人的精神攻击不继承 Brutal 等普通攻击能力。
12. Apocalypse Dragon 单次高攻击降低多个头部等级，但等级到战斗结束才移动。
13. 个人任务放弃后降低声望并转换为中立进度。
14. Mana Shard 的惩罚无法落到可修改效果时产生伤牌。
15. 存档、刷新页面、继续后，随机结果和事件日志保持一致。
